## 1. Findings per tool (evidence + URLs)

### Takeaway
The only software that is genuinely necessary for a lean, agent-assisted UE5 asset pipeline is **Blender 5.2 LTS** (free, GPL, scriptable, has official and community MCP bridges) plus **one texturing/baking tool** (Substance 3D Painter is the industry default; Material Maker/ArmorPaint are free fallbacks). Everything else (Maya, ZBrush, Marmoset, RizomUV, Quad Remesher, Simplygon/InstaLOD, Marvelous Designer, Houdini) is situational or duplicative. **Steam-release licensing gate:** Blender passes with no restriction; Maya Indie, Houdini Indie, RizomUV Indie, InstaLOD Pioneer and Quad Remesher "Indie" all carry revenue/funding/project-value caps (or a non-commercial restriction) that a successful commercial Steam game can exceed; Substance's Steam-edition revenue terms are *not* stated in any current primary document I could find (UNVERIFIED), so get Adobe's answer in writing or use the Adobe subscription.

## 4. UE import / prep checklist (conversion, compression, LOD, Nanite, collision, materials)

### Takeaway
Use FBX through Interchange for meshes and skeletal/animation, GLB where a light format suffices, USD only experimentally; keep scene scale 1.0 in Blender and verify normals/Recompute Normals on import; enable Nanite on opaque/masked static meshes, keep fallback LODs; author simple convex collision (UCX) for gameplay and use Simple-as-Complex elsewhere; pack ORM with sRGB off; decide on Substrate at project start.

### Cited Findings
Evidence for each line item is in Section 1 (Unreal Engine side). Key sources: [Nanite overview](https://web.archive.org/web/2026/https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine), [Nanite Technical Details](https://dev.epicgames.com/documentation/unreal-engine/nanite-technical-details?lang=en-US), [Epic LOD/fallback staff answer](https://forums.unrealengine.com/t/questions-on-best-practices-for-nanite-lod-interaction-and-ism-hism-combination/2672255), [Interchange threads](https://forums.unrealengine.com/t/fbx-import-changed/2144275), [Interchange USD status](https://forums.unrealengine.com/t/interchange-usd-import-in-ue-5-6-unsupported-schemas-incomplete-blueprint-conversion-block-production-adoption/2653604), [Substrate talk](https://www.youtube.com/watch?v=SqPaL8HS_Lw), [UE 5.8 performance notes](https://tomlooman.com/unreal-engine-5-8-performance-highlights/), [UCX forum threads](https://forums.unrealengine.com/t/fbx-ucx-collision-meshes-not-working/353934), [texture packing guides](https://normalmapmaker.com/guides/normal-map-for-unreal/).

### Inferences

**A. Format and conversion**
1. FBX is the safe default for static meshes, skeletal meshes and animation (Interchange FBX default since 5.4/5.5; legacy via `Interchange.FeatureFlags.Import.FBX False`). GLB/glTF is fully Interchange-supported (good for AI-generator output and simple props; Blender 5.2 exports meshopt and more). USD in Interchange was still experimental for scene import in 5.6; do not base production assets on it until the 5.8 status is checked (UNVERIFIED).
2. After each engine upgrade, re-run an import regression test: check `Recompute Normals` (5.5 default discarded DCC smoothing), tangent/UV handling and Nanite flag; Nanite derives tangents in the pixel shader, so baking and shading consistency should be checked on Nanite meshes.
3. Blender export: scene unit scale 1.0 (Epic's tool only checks 1.0), apply transforms, correct forward/up per exporter preset, export Edge/Face smoothing (not "Normals Only" blindly), triangulate only for non-Nanite or when needed, one exporter settings dict in a repo script (agent-maintained).

**B. Naming/structure:** `SM_`, `SK_`, `T_<name>_BC/N/ORM`, `MI_`, collision `UCX_<exact mesh name>_NN`; one script validates names, units, pivots (corner-on-floor grid pivot for modular kits), material slot count (target 1 per mesh), UV channel layout.

**C. Textures:**
- Base Color: sRGB on, BC1/BC7. Normal: DirectX −Y, sRGB off, Normal Map (BC5). ORM (R=AO, G=Roughness, B=Metallic): sRGB off, "Masks" compression. Emissive/opacity separate. Use virtual textures for large unique textures (Epic: "highly recommended" with Nanite).
- Texel density: set one project number (512 px/m baseline for third-person environments; 1024 px/m for hero/cover props viewed close; trim sheets obey the same number). Keep ORM and normals at identical resolution to avoid extra samplers.
- Keep separate source maps for repacking; verify compression artifacts after cooking.

**D. Nanite:**
- Enable on static meshes with many triangles/instances and major occluders (opaque or masked). Do not rely on Nanite for translucent glass, mesh decals, morph-target deformation; keep Nanite off for those. For foliage: cut-out geometry + opaque where possible; Preserve Area only on foliage; clamp WPO and set WPO disable distance (5.8 extends this to skinned meshes).
- Nanite skinned meshes (`r.Nanite.AllowSkinnedMeshes`, since 5.5) — treat as unproven for hero characters until the maturity label in 5.8 is confirmed (no morphs per docs).
- Nanite foliage/PVE: Experimental through 5.8; no ray tracing support for Nanite foliage — avoid depending on it for shipping vegetation.
- Disable "Generate Lightmap UVs" unless using baked lighting.
- Nanite requires DX12 SM6 hardware; define a non-Nanite fallback policy (Fallback Relative Error, Min LOD) for lower tiers.

**E. LOD:** Nanite replaces manual LOD chains for rendering but you still need fallback LODs for complex collision, ray tracing/Lumen HWRT, RVT, non-Nanite platforms. Practical default (Epic staff): Num LODs ≈ 4, Fallback Relative Error > 1 to auto-generate LODs inside UE. Authored LODs (or impostors/HLOD) remain for skeletal meshes without Nanite, translucent/alpha-heavy meshes, vehicles and any non-Nanite target. External LOD tools (Simplygon/InstaLOD) are only justified for console/handheld non-Nanite targets.

**F. Collision:** For gameplay-relevant props author 1–N convex `UCX_` hulls; import with Auto Generate Collision and One-Convex-Hull-Per-UCX off; for static architecture prefer Use Simple as Complex with simple hulls; use per-poly complex collision (which uses the fallback mesh with Nanite) sparingly. Chaos Visual Debugger (5.8, adds a triangle-mesh complexity view) helps audit physics scene complexity — [Tom Looman](https://tomlooman.com/unreal-engine-5-8-performance-highlights/).

**G. Materials:** One master material per surface class (architecture trim, metals/painted, glass, fabric, decal) with exposed parameters (tiling, offset, tint, roughness/metal/normal strength, wear/dirt via vertex color); material instances only per asset. Substrate: on by default in new 5.7+ projects; legacy materials still work; choose at project start, minimize slabs, avoid expensive SSS/anisotropy by default (static switches), check the 5.8 shader-count overlay. Decals and trim sheets for repetition breaking; Substrate decal method (blendable vs DBuffer) must be chosen consistently.

**H. In-engine validation:** Nanite visualization (Mask, Triangles, Clusters, Overdraw), shader complexity, fallback-mesh view, Lumen scene view, shader count in Material Editor, stat GPU/Insights, texel density view mode. Script an audit that exports a CSV (tri counts, material slots, texture sizes, collision type, Nanite flag) per asset.

### Gaps
- Epic's own FBX-pipeline, collision and texture documentation pages could not be read (HTTP 403); UCX/texture rules rely on Epic-forum and third-party sources and should be spot-checked in the engine.
- 5.8 status of: Nanite skinned meshes, Nanite foliage label, Interchange FBX normal defaults, Interchange USD, `UE 5.8 Python Interchange API` page (only 5.7 Python docs read).
